# Afternoon texts, am-start, SMS responder, dispatcher, line/call watch, KPI scorecard

### Afternoon voicemail texts + caller audit (`src/pm_text_sender.py`, built 2026-10-20)

Rahaf's Jackson P1 attempt = automated morning text (drip), call, voicemail, afternoon text to every number she left a voicemail on. The afternoon text was the one manual step and on launch day (2026-10-19) 0 of 47 went out, so it's now a scheduled job (`.github/workflows/pm-text-sender.yml`, 4:30 PM Central Mon-Fri; a second job posts an end-of-day caller checklist to Slack at 7:15 PM).

- **Voicemail detection** = outbound call by Rahaf that smrtPhone logged as *answered* for ≥20s, on a number she marked **No Answer** that day. Backtested against transcripts of all 72 launch-day recordings (two independent audio-model passes, only agreements counted): 45 of 48 real voicemails matched, 3 misfires. Her phone mark is the gate, so "mark every number you dial" is the only manual step left. **The mark carries over (fixed 2026-10-20):** the first live day only counted a No Answer mark made that day, which missed every number Rahaf had already marked No Answer on 10/19 (re-clicking the icon would clear it, and the smrtPhone pop-up dispo writes it once) — 24 of 29 voicemails skipped. `final_mark()` now falls back to the phone's stored status; only UNKNOWN/blank counts as never marked. Hard skips: number later marked Correct/Wrong/Dead/DNC, owner dnc/opt-out, record no longer Prospecting, number replied or called back that day, already texted from an afternoon line that day.
- **Why not a DataSift drip:** drips text the primary phone (or all Correct phones); only 18 of the 48 voicemail numbers on launch day were the record's primary phone. The script texts the exact number via **smrtPhone's SMS API** — `POST https://phone.smrt.studio/sms/send`, header `X-Auth-smrtPhone: <token>`, form fields `from`/`to`/`message` — which resolves from Kaycie's machine even though `api.smrtphone.io` does not. Verified live 2026-10-20 (HTTP 200 + smsId). An internal line on smrtPhone's own DNC list (e.g. the 955-3574 callback line) returns HTTP 400 "This number is on your DNC list".
- Day 1-5 wording comes from the record's Call Attempts counter (after today's bump, or +1 if not bumped yet). Round-robin across the three afternoon lines, hard cap 20 per line per day; overflow is reported, never sent. Scheduled sends only inside 16:15-17:00 Central (`--only-between`), so a GitHub-delayed run can't text at dinner time. Two crons per job (CDT/CST) because GitHub cron has no time zone.
- **Triggering (changed 2026-10-20, first live day).** GitHub's own `schedule:` crons started ~4 hours late that day, so the 4:30 job never fired inside its window and 0 of 35 planned texts went out (sent by hand that evening with `--force`). All three jobs are now started by a **Cloudflare Worker**, `dispatcher/` (`siftstack-dispatcher`, deployed with `npx wrangler deploy` from that folder), whose cron triggers fire on the minute and call `workflow_dispatch` with `mode=<job>` and `gate=true`; `gate=true` makes the workflow apply the same Central time window the schedule path uses. Needs a fine-grained GitHub PAT (Actions read+write on this repo only) stored as the Worker secret `GITHUB_TOKEN` (created 2026-10-21, **expires 2026-10-21 + 1 year, Oct 2027**: create a new fine-grained PAT and run `npx wrangler secret put GITHUB_TOKEN` from `dispatcher/`, or the three jobs silently stop). **Deployed 2026-10-21** to Kaycie's Cloudflare account (kaycie@bluetailhomes.com, account `9a30a49b2f4fdfd1f690dcccdd845492`, workers.dev subdomain `bluetailhomes`): status page `https://siftstack-dispatcher.bluetailhomes.workers.dev/` (shows the Central time it sees, the next slot, and whether the token is set); manual run `POST .../run/<am-start|pm-texts|audit>` with header `X-Dispatch-Key` = `DISPATCHER_KEY` in `.env` (the worker always sends `gate=true`, so even a manual run respects the job's window). Workers Free allows only 5 cron triggers per account, so each job has ONE cron listing both UTC hours (`50 14,15 * * MON-FRI` etc.) and the worker's Central-clock check makes the wrong-hour firing a no-op. Use day NAMES in Cloudflare crons, not numbers: Cloudflare counts 1 = Sunday (GitHub counts 0 = Sunday), so `1-5` meant Sun-Thu and every Friday dispatch was skipped until the 2026-10-25 fix. Verified 2026-10-21: a manual dispatch created the GitHub run 1 second later (vs. 3-7 h late on GitHub's own cron the day before). On this laptop run wrangler as `npx.cmd wrangler ...` (PowerShell's script policy blocks `npx`); login state lives under `%APPDATA%\xdg.config\.wrangler\`. **The SMS auto-responder (`.github/workflows/sms-auto-responder.yml`) is dispatched the same way since 2026-10-21**: the worker's `sms-responder` interval job fires it every 5 minutes 07:00-22:59 Central, every day, with `since_minutes=180`; its own GitHub cron was removed because GitHub ran it only 3 times in 9 hours on 10/20 (with a 20-minute lookback, most replies were never drafted) and a second trigger could draft the same reply twice. The worker uses all 5 of the free plan's cron triggers (the fifth is the Sunday weekly top-up: 6:00 PM Central, `.github/workflows/weekly-topup.yml` running `src/weekly_topup.py apply`, dry run until repo variable `TOPUP_LIVE` is `"true"`, and it refuses if that Monday's Batch tag already exists unless `--force`; the Slack report, dry runs included, opens with a "Batch YYYY-MM-DD already exists" warning in that case); the drip exit guard stays on GitHub cron (lateness there only delays a removal until well before the next morning's drip step). Fallbacks: am-start and audit keep their GitHub crons (harmless to run twice). pm-texts has **no** GitHub cron and must not get one back, because the "already texted today" check depends on DataSift logging API-sent SMS (verified 2026-10-22, but it can lag a few seconds); its only backup is the Windows Task Scheduler job on Kaycie's machine, `SiftStack PM Texts` (runs `scripts/pm_texts_local.cmd` Mon-Fri 4:00 PM Mountain = 5:00 PM Central, `--only-between 17:00-17:45`, logs to `logs/pm_texts_local.log`, interactive-only so Kaycie must be logged in), a slot that never overlaps the dispatcher's 16:15-17:00 send. **That Windows task is DISABLED as of 2026-10-21** (Kaycie's call: one reliable trigger with a Slack failure alert beats two triggers that could double-text ; the DataSift SMS-sync question was later answered yes on 2026-10-22); re-enable with `schtasks /Change /TN "SiftStack PM Texts" /ENABLE` if a backup is wanted.
- **Dry run by default.** Sends only when the repo Actions variable `PM_TEXTS_LIVE` is `"true"`. Needs repo secret `SMRTPHONE_API_TOKEN` (same value as `.env`). Backtest any day with `python src/pm_text_sender.py pm-texts --day YYYY-MM-DD`; `audit --day YYYY-MM-DD` prints the checklist. Plans/results land in `output/pm_texts/`.
- **Extra-number confirmation texts (`extra-texts`, added 2026-10-22):** up to two texts, ever, to each mobile number beyond #1/#2 on a Jackson P1 record: a confirmation text, then one follow-up on a later day if that number never replied (added 2026-10-22; skipped if the number has any other SMS history, so nothing gets a third text) (calls and the drip stay on #1/#2), sent from SMS Line A-E. Only numbers tagged Dial First-Fourth (Dial Fourth added 2026-10-22). A record is skipped entirely once any of its phones is marked Correct (added 2026-10-22: the owner is already reached, so no more texts to extra numbers). The 20-per-line daily cap counts every text that line already sent that day (from DataSift's `owner.sms.sent` history, drip and manual included), not just this job's. Runs as a second step of the pm-texts job (same dispatcher trigger, same 16:15-17:00 Central gate, no extra cron). Dry run with a Slack report until the repo variable `EXTRA_TEXTS_LIVE` is `"true"`. The "already texted" check relies on DataSift's SMS history, since the job's local state files don't persist between GitHub runs.
- **Line volume watch (`line-watch`, added 2026-10-23):** alerts Google Chat and Slack ("Line 816-xxx-xxxx has sent N texts today — stop texting from it.") when any of our SMS lines (SMS Line A-E plus the three afternoon lines) passes 20 texts in a Central day, then again at every 5 more, to keep lines under carrier spam flags. Counts DataSift's `owner.sms.sent` log (`/property/logs/`, paged by cursor until it reaches the previous day), so drip, manual and API texts all count. No saved state: each run alerts only on thresholds crossed in the last `--window-min` (default 5) minutes, matching the dispatcher's 5-minute cadence. Runs as a third `if: always()` step of the SMS auto-responder job (`.github/workflows/sms-auto-responder.yml`); `dry_run=true` passes `--no-post` (prints only). Backtest a past day with `python src/pm_text_sender.py line-watch --day YYYY-MM-DD --no-post`, which reports every crossing that day. Tests: `tests/test_line_watch.py`.
- **Inbound call watch (`call-watch`, added 2026-10-26):** posts every inbound call and voicemail on our lines (SMS Line A-E, the afternoon lines, the callback line) to Google Chat "Seller Texts" and Slack: "Incoming call: (caller) (owner names, or not in DataSift) called SMS Line X ... at 10:02 AM — left a voicemail / talked Ns / missed call, no voicemail", with the recording link when there is one. Reads `owner.call.received`/`owner.call.missed` rows with `direction=inbound` from `/property/logs/`, grouped by the call's `external_id` (one call fans out to every owner sharing the number). No saved state: looks back `--window-min` (default 6) minutes against the 5-minute dispatcher cadence, so a rare overlap can post one call twice. Runs as the fourth `if: always()` step of the SMS auto-responder job; `dry_run=true` passes `--no-post`. Backtest with `python src/pm_text_sender.py call-watch --day YYYY-MM-DD --no-post`. **The voicemail format is unverified:** no real voicemail had reached the feed when it was built (2026-10-26 backtest found only 2 missed calls), so check the first real one. Background: Rahaf now calls from the same lines she texts from, so texts no longer need a "call me back at" number. Tests: `tests/test_call_watch.py`.
- **Unmatched replies (`sms_auto_responder.py`, added 2026-10-26):** a reply from a number on no DataSift record is matched by line: the responder lists the texts we sent from that same line in the 24 hours before the reply (`owner.sms.sent`). If one property was texted, that's the match; if several were, it matches only when the reply names one's street name or house number. A line-matched reply is always needs-human and never pulls the record's drip (the number isn't the dripped one). A STOP adds the replying number to the matched owner as CORRECT_DNC (or marks it, if it's already on the owner). A reply that can't be placed is flagged to Slack and Google Chat as "needs a human" with the candidate addresses; STOPs post to both Slack and Google Chat (changed 2026-10-26). No saved state: it is flagged only while the reply is at most 6 minutes old (`UNMATCHED_FLAG_WINDOW_MIN`), so each run flags it once. A dry run posts and writes nothing. Tests: `tests/test_unmatched_reply.py`.
- **KPI scorecard (`src/kpi_scorecard.py`, built 2026-10-26):** Rahaf's 8 KPIs, read from the same `load_day()` models, so she does no extra reporting. Daily lines are added to the end of the 7:15 PM audit post: dials vs. the 150 floor, CN contacts (answered outbound calls to a number whose final mark is Correct/Correct-DNC), conversations ≥60s (floor 10, goal 20) and ≥120s, the three dialing blocks (10:15 / 14:00 / 16:45 Central, ±45 min), new-number marking, and a Gaps line. The weekly section goes in the Sunday top-up Slack report (`weekly_topup.kpi_week()`, prior Mon-Fri): conversation rate (only judged once there are ≥100 CN calls), sellers advanced by tier (each record counted once, at its highest tier), qualified leads (proxy: Hot or better; floor 1, goal 5), photos and offers, engaged sellers with a dated task, and the latest coaching averages from `output/call_coaching/`. Both hooks sit in try/except, so a KPI failure never breaks the audit or the top-up. It was built before the "5 clean automation days" gate was met (10/20 pm-texts never fired; 10/23 skipped by the Cloudflare day-number bug), so targets stay at the floors until two clean weeks give a baseline. A missed floor is shown as a gap and the floor is never lowered; conversations and qualified leads are labeled as coached numbers. Tests: `tests/test_kpi_scorecard.py`.

Marking a number WRONG makes DataSift clear it as primary, so am-start cannot re-drip that record. Tests: `tests/test_drip_stop.py`. Live-verified once on the 2905 E 52nd St record; the scheduled jobs pick the change up only after it is on `main`. **Widened 2026-10-21 (same day):** the responder now pulls the drip on ANY reply from the primary phone, whatever the category (a question or an interested owner should hear from Rahaf, not from the next automated text); It still drafts the reply and flags as before. **Narrowed again 2026-10-21:** a reply from a non-primary number never pulls the drip, not even a STOP (a wrong number saying STOP must not pull the owner from marketing). The exit guard also now runs as a second step (`if: always()`) of the SMS auto-responder job, so it fires every 5 minutes on the dispatcher's clock; its own `*/15` GitHub cron stays as a fallback (idempotent).
- **Morning start (`am-start`, added 2026-10-20):** a 9:50 AM Central job replaces Rahaf's 10:00 "Select All → Prospecting". It reads preset `01.
