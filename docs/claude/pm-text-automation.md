# Afternoon texts, am-start, SMS responder, dispatcher, line/call watch, KPI scorecard

### Afternoon voicemail texts + caller audit (`src/pm_text_sender.py`, built 2026-10-20)

Rahaf's Jackson P1 attempt = automated morning text (drip), call, voicemail, afternoon text to every number she left a voicemail on. The afternoon text was the one manual step and on launch day (2026-10-19) 0 of 47 went out, so it's now a scheduled job (`.github/workflows/pm-text-sender.yml`, 4:30 PM Central Mon-Fri; a second job posts an end-of-day caller checklist to Slack at 7:15 PM).

- **Voicemail detection** = outbound call by Rahaf that smrtPhone logged as *answered* for ≥20s, on a number she marked **No Answer** that day. Backtested against transcripts of all 72 launch-day recordings (two independent audio-model passes, only agreements counted): 45 of 48 real voicemails matched, 3 misfires. Her phone mark is the gate, so "mark every number you dial" is the only manual step left. **The mark carries over (fixed 2026-10-20):** the first live day only counted a No Answer mark made that day, which missed every number Rahaf had already marked No Answer on 10/19 (re-clicking the icon would clear it, and the smrtPhone pop-up dispo writes it once) — 24 of 29 voicemails skipped. `final_mark()` now falls back to the phone's stored status; only UNKNOWN/blank counts as never marked. Hard skips: number later marked Correct/Wrong/Dead/DNC, owner dnc/opt-out, record no longer Prospecting, number replied or called back that day, already texted from an afternoon line that day.
- **Why not a DataSift drip:** drips text the primary phone (or all Correct phones); only 18 of the 48 voicemail numbers on launch day were the record's primary phone. The script texts the exact number via **smrtPhone's SMS API** — `POST https://phone.smrt.studio/sms/send`, header `X-Auth-smrtPhone: <token>`, form fields `from`/`to`/`message` — which resolves from Kaycie's machine even though `api.smrtphone.io` does not. Verified live 2026-10-20 (HTTP 200 + smsId). An internal line on smrtPhone's own DNC list (e.g. the 955-3574 callback line) returns HTTP 400 "This number is on your DNC list".
- Day 1-5 wording comes from the record's Call Attempts counter (after today's bump, or +1 if not bumped yet). Round-robin across the three afternoon lines, hard cap 20 per line per day; overflow is reported, never sent. Scheduled sends only inside 16:15-17:00 Central (`--only-between`), so a GitHub-delayed run can't text at dinner time. Two crons per job (CDT/CST) because GitHub cron has no time zone.
- **Triggering (changed 2026-10-20, first live day).** GitHub's own `schedule:` crons started ~4 hours late that day, so the 4:30 job never fired inside its window and 0 of 35 planned texts went out (sent by hand that evening with `--force`). Workers Free allows only 5 cron triggers per account, so each job has ONE cron listing both UTC hours (`50 14,15 * * MON-FRI` etc.) and the worker's Central-clock check makes the wrong-hour firing a no-op. Use day NAMES in Cloudflare crons, not numbers: Cloudflare counts 1 = Sunday (GitHub counts 0 = Sunday), so `1-5` meant Sun-Thu and every Friday dispatch was skipped until the 2026-10-25 fix. Verified 2026-10-21: a manual dispatch created the GitHub run 1 second later (vs. 3-7 h late on GitHub's own cron the day before). The worker uses all 5 of the free plan's cron triggers (the fifth is the weekly top-up: 6:00 PM Central on **Fridays** since 2026-11-13 (moved from Sunday; Sunday 2026-11-08 was the last Sunday run, kept by a one-day `onDate` entry in the worker's JOBS; the cron is `0 0,23 * * FRI,SAT,SUN,MON` and SUN,MON can be dropped after that date). - **Line volume watch (`line-watch`, added 2026-10-23):** alerts Google Chat and Slack ("Line 816-xxx-xxxx has sent N texts today — stop texting from it.") when any of our SMS lines (SMS Line A-E plus the three afternoon lines) passes 20 texts in a Central day, then again at every 5 more, to keep lines under carrier spam flags. Counts DataSift's `owner.sms.sent` log (`/property/logs/`, paged by cursor until it reaches the previous day), so drip, manual and API texts all count. No saved state: each run alerts only on thresholds crossed in the last `--window-min` (default 5) minutes, matching the dispatcher's 5-minute cadence. **Stateful since 2026-11-17:** the workflow passes `--state output/watch_state/line_watch.json`, which remembers the highest level alerted per line today, so a late or skipped run still alerts once (at the current level) instead of missing a crossing; without the file (cache miss, first run of the day) it falls back to the window. Runs as a third `if: always()` step of the SMS auto-responder job (`.github/workflows/sms-auto-responder.yml`); `dry_run=true` passes `--no-post` (prints only). Backtest a past day with `python src/pm_text_sender.py line-watch --day YYYY-MM-DD --no-post`, which reports every crossing that day. Tests: `tests/test_line_watch.py`.
- **Inbound call watch (`call-watch`, added 2026-10-26):** posts every inbound call and voicemail on our lines (SMS Line A-E, the afternoon lines, the callback line) to Google Chat "Seller Texts" and Slack: "Incoming call: (caller) (owner names, or not in DataSift) called SMS Line X ... at 10:02 AM — left a voicemail / talked Ns / missed call, no voicemail", with the recording link when there is one. Reads `owner.call.received`/`owner.call.missed` rows with `direction=inbound` from `/property/logs/`, grouped by the call's `external_id` (one call fans out to every owner sharing the number). No saved state: looks back `--window-min` (default 6) minutes against the 5-minute dispatcher cadence, so a rare overlap can post one call twice. **Stateful since 2026-11-17:** with `--state output/watch_state/call_watch.json` it looks back to the previous run (minus 2 min, at most 12 h) and skips calls already posted, so skipped dispatcher runs lose nothing and overlaps no longer double-post. Runs as the fourth `if: always()` step of the SMS auto-responder job; `dry_run=true` passes `--no-post`. - **Unmatched replies (`sms_auto_responder.py`, added 2026-10-26):** a reply from a number on no DataSift record is matched by line: the responder lists the texts we sent from that same line in the 24 hours before the reply (`owner.sms.sent`). If one property was texted, that's the match; if several were, it matches only when the reply names one's street name or house number. A line-matched reply is always needs-human and never pulls the record's drip (the number isn't the dripped one). A STOP adds the replying number to the matched owner as CORRECT_DNC (or marks it, if it's already on the owner). No saved state: it is flagged only while the reply is at most 6 minutes old (`UNMATCHED_FLAG_WINDOW_MIN`), so each run flags it once. A dry run posts and writes nothing. Tests: `tests/test_unmatched_reply.py`.
